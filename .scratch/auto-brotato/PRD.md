# PRD：AutoBrotato 全自动对局系统

> 状态：已评审确认（2026-10-06）
> 关联：[architecture.md](../../docs/architecture.md)、[protocol.md](../../docs/protocol.md)、[strategy.md](../../docs/strategy.md)、[docs/adr/](../../docs/adr/)

---

## 1. 背景与问题

用户希望在 Brotato（单机肉鸽，Steam app 1942280，Godot 引擎）中：人工选好英雄与初始武器、进入难度选择页后，由系统读取当前选择、询问难度并**全自动高水平地打完整局**。

本机已有一套实机验证的 AutoBrotato mod 0.2.0（观测 60Hz / move 注入 / 商店动作 / IPC），但源码仅存于 workshop zip，Python 决策端与文档缺失。本 PRD 与关联文档即为补齐设计、并规划实现。

## 2. 用户故事

> 我手动打开 Brotato，选好游侠和初始武器，停在难度选择页。
> 终端里系统已经打印："检测到英雄：游侠；初始武器：XX；可选难度：D0–D1；模式开关：…"
> 我输入 `D0` 回车。系统自动把难度滑杆设到 D0、点击开始，随后自动打完全部 20 波（含商店购物、升级选卡）。
> 结束时终端打印战报（胜负、波次、时长、经济、构建、回放路径），我复盘或开始下一局。

## 3. 功能需求

| # | 需求 | 说明 |
| --- | --- | --- |
| F1 | 难度页检测与信息读取 | 读取英雄 ID、初始武器、难度解锁范围内、模式开关；终端展示 |
| F2 | 难度选择交互 | 接受任意**已解锁**难度（运行时读取上限，不硬编码 D0）；非法输入重问 |
| F3 | 自动开局 | 设置难度滑杆 → 开始对局，读回校验 |
| F4 | 全自动战斗 | 60Hz 观测驱动的自动走位/避弹/风筝；瞄准与开火由游戏 auto-aim 完成 |
| F5 | 全自动商店 | 购买/出售/刷新/锁定/离开，评分决策（Tier + 经济规则） |
| F6 | 全自动升级选卡 | 波间升级项评分与选择 |
| F7 | 胜败检测与战报 | 第 20 波胜利 / 死亡检测；打印结果、波次、时长、经济、构建、回放路径 |
| F8 | 回放与复盘 | 每局 NDJSON 落盘；离线回放回归与调参 |
| F9 | 安全停住与接管 | 断连 TTL 归零；Ctrl+C/stop 让出控制；重连需 resume 才接管 |

## 4. 非功能需求

- **合规**：只经游戏正常输入与 UI 信号，不直接改游戏状态/存档；单机本地，不联机。
- **稳定**：验收配置下 D0 连续 10 局 ≥9 胜（见 §6）。
- **可观测**：终端状态日志 + 可选调试叠加层；战报含回放路径。
- **可维护**：锁游戏版本 1.1.15.4 + 握手校验 + 冒烟清单；协议契约文档化。
- **环境**：开发与运行均在 conda 环境 `brotato`（Python 3.12）。

## 6. 验收标准

**基准配置**：英雄 `character_ranger`（游侠），初始武器由用户在验收时指定并记录。

1. D0，连续 10 局自动对局：**≥9 局通关**（第 20 波胜利）；
2. 每局除"输入难度"外无人工干预；
3. 不使用暂停、时间加速、作弊或直接修改游戏状态；
4. 每局产出回放与战报；失败局可离线复盘。

## 7. 非目标

- 不自动选择英雄/初始武器；不自动重试/连刷；不自动切换难度。
- 首版不承诺全英雄胜率、不做 D1+ 专项策略、不做学习型策略。
- 不改动游戏文件/存档；不发布 Workshop 物品。
