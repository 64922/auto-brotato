# 决策引擎与策略设计（strategy.md）

> 状态：设计基线（2026-10-06 确认，ADR-0002 分层启发式）。随票据 09–13 逐步实现与调优；权重与阈值类数值全部外置配置，本文只定结构与规则。
>
> 关联：[architecture.md](./architecture.md) §7、[protocol.md](./protocol.md)（观测字段定义）。

---

## 1. 输入、输出与约束

- **输入**：`snapshot`（60Hz，见 protocol.md §3.1）、`shop`、`menu`（升级页）、`event`。
- **输出**：`move` 向量（唯一的高频输出）；`shop_*` 与 `menu_*` 动作（低频、串行、幂等）。
- **约束**：
  - 战斗控制只有移动：**瞄准与开火由游戏 auto-aim 完成**（`manual_aim=false`）。
  - 动作有 TTL（250ms）：反射层必须稳定续发，不能因长耗时计算断流。
  - 观测可能在极端波次被截断（`truncated=true`）：决策必须容忍盲区。

## 2. 三层结构

```
                ┌────────────────────────────────────────────────────┐
                │                    经济层（事件驱动）                │
                │  商店评分/购买/出售/刷新/锁定 · 升级选卡 · 经济规划    │
                └───────────────▲──────────────────────┬─────────────┘
                                │ 目标/约束（如“攒钱到第5波”）  │ shop_* / menu_*
                ┌───────────────┴──────────────────────▼─────────────┐
                │                战术层（3–5Hz）                       │
                │  目标选择（材料/Boss/安全位）· 采集与血量管理 ·       │
                │  波次节奏 · 给反射层的“期望位置/期望距离”            │
                └───────────────▲──────────────────────┬─────────────┘
                                │ 期望位置/距离/权重      │
                ┌───────────────┴──────────────────────▼─────────────┐
                │                反射层（30–60Hz）                     │
                │  危险场构建 · 候选方向评估 · 边界/风筝 · 平滑         │
                │  → move 向量（每 1–2 帧发送）                        │
                └────────────────────────────────────────────────────┘
```

- **反射层**是唯一直接生成 `move` 的模块，保证频率与平滑；
- **战术层**慢频决策，只改"目标与权重"，不直接控制移动；
- **经济层**在商店/升级事件时运行一次，可长时间计算（毫秒级无压力），不介入战斗循环。

## 3. 反射层：走位与避弹（票据 09）

### 3.1 危险场

对每个危险源计算"到达代价"：

| 危险源 | 建模 |
| --- | --- |
| 敌人（近战） | 位置 + 速度外推（0.3–0.8s 时间窗）+ 碰撞半径 + 少量缓冲 |
| 敌人（远程/精英/Boss） | 同上 + 攻击警告（Boss 技能以实测模式补规则） |
| 敌方弹幕 | 位置 + `vel` 线性外推 + `ttl` 截断 + 半径 |
| 地雷 | 静态危险圈（半径 + 缓冲），不追拾取 |
| 场地边界 | 边距排斥（贴边是战术，不是常态） |

- 时间窗内做多次采样（如 0.15/0.3/0.5/0.8s）叠加成"不可达代价"。
- `truncated=true` 时提高保守权重（盲区按最近截断距离推定危险密度）。

### 3.2 候选方向评分（每帧）

在 16 或 24 个候选方向（含当前方向）上评分，选最优：

```
score(dir) = −Σ 危险代价(predicted_pos(dir))
             − 边界惩罚
             − 与战术期望位置的距离代价
             − 转向抖动惩罚（与前几帧方向差的平滑）
             + 移动收益（如接近材料/保持风筝距离带）
```

- 输出向量经模长钳制后发送；使用低通/指数平滑避免 8 向 PWM 下的抖振。
- **风筝（kiting）**：对近战敌人维持"理想距离带"（由武器射程与敌人速度决定，默认射程的 45%–65%）；对弹幕敌人优先横向位移出弹道。
- **贴边策略**：仅在开阔场中央受挤压时使用，常规保持中距机动。

### 3.3 血量紧急策略

- `hp/max_hp < 阈值`（如 30%）→ 提高危险权重、优先接近回血消耗品、放弃远距离材料。
- `invuln=true`（受伤无敌帧）→ 允许穿越一次弹幕以脱离包围（配置开关）。

## 4. 战术层：目标与节奏（票据 10）

- **目标选择（3–5Hz）**：
  - 材料簇：贪心 + 距离衰减；避开高危险区；
  - 血量：低血时把最近 consumable 视为最高价值目标；
  - Boss：波次结束前拉锯战，维持射程带与场地开阔方向。
- **波次节奏**：早期（1–8 波）偏采集扩张；中后期（9–20 波）偏生存与安全走位；最后一波只求稳态输出。
- **材料收集窗口**：波次末段清场后（剩余敌人数少）集中拾取。
- 输出给反射层：期望位置（可选）+ 目标距离带 + 权重向量。

## 5. 经济层：商店与升级（票据 12）

### 5.1 商店评分

对槽位中每件商品计算边际收益评分：

```
value(item) = Σ_stat 属性价值(权重[英雄/构筑][stat] × 物品属性增量)
              + 特殊效果分（按规则表，如武器类联动、负面代价扣分）
              + 数量/协同分（同武器合并升级、套装联动）
              − 价格机会成本（价格 / 当前经济阶段边际金币价值）
```

- 购买规则：`value > 阈值` 且金币安全余量足够；同 id 武器优先凑 2 合并（Brotato 规则：同 id 同级两把自动合并升级）。
- 刷新：仅当"现有槽位全部低价值"且预算允许；刷新预算按波次增长曲线（外置参数）。
- 锁定：发现高价值但当前买不起 → 锁定（`keep_lock` 设置开启时跨波保留）。
- 出售：仅在需要金币购买关键物或武器位满且低价值时卖武器（道具不可卖）。

### 5.2 升级选卡（`level_up`）

- 与商店同样的属性价值函数，不含价格项；
- 优先补齐构筑短板（按当前 stats 分布计算"最缺属性"），而非单一最强项；
- 英雄/构筑权重表驱动（Ranger：远程伤害 > 攻速 ≈ 暴击 > 生存）。

### 5.3 经济节奏（粗规则，外置参数）

- 早期不过度刷新（保留现金）；
- 波次 5 / 10 / 15 前保证关键构筑节点（武器位、核心属性阈值）；
- 金币安全余量随波次递减（后期允许花光）。

## 6. 英雄与武器适配

- **适配接口**：`HeroProfile`（属性权重、特殊机制规则、理想距离带、开局武器倾向）与 `WeaponClass`（近战/远程、射程带、AoE/投射物特征）。
- **首批（验收基准）**：游侠 Ranger —— 远程风筝基线：
  - 理想距离带取武器射程的 45%–65%；
  - 属性权重：`ranged_damage`、`attack_speed`、`crit_chance` 优先；
  - 初始武器以用户指定为准，引擎按武器射程自动定带。
- 其他英雄：架构通用（读英雄 ID 走同一管线），无专门 `HeroProfile` 时使用"通用远程/近战"兜底权重（尽力而为，不承诺胜率，ADR/Q2 决策）。

## 7. 知识库（票据 11）

**生成方式**：mod 侧调试动作 `debug_export_knowledge`（`mod/src/knowledge_export.gd`）从游戏运行时资源（`/root/ItemService`、`/root/ChallengeService`）导出；`tools/export_knowledge.py` 收集到 `docs/knowledge/`（默认导出两次并校验逐字节一致）；`tools/verify_knowledge.py` 以游戏 PCK 静态资源为基准做覆盖性与抽样字段对照。

```
docs/knowledge/
├── items.json        # 物品：id、名称、tier、price、属性增量（stat_deltas）、特殊效果、标签
├── weapons.json      # 武器：id、名称、tier、price、类别、stats、套装、合并链
├── upgrades.json     # 升级项：id、属性增量、效果、上限限制（max_nb）
├── characters.json   # 英雄：id、基础属性（effects/stat_deltas）、初始武器池、解锁（默认/挑战）
└── tier_list.json    # 人工标注：物品/武器强度评级与备注（随版本更新）
```

- 每个导出文件含 `schema_version`、`game_version`（锁定 1.1.15.4）、`data_version`（对条目规范 JSON 的 SHA-256，作为知识库版本标识）与 `entries`（按 id 排序，同版本重复导出稳定）；`weapons.json` 另含顶层 `sets`（套装加成按件数分层）。
- **字段口径**：`stat_deltas` 与游戏 `Effect.apply()` 一致（SUM 存储按 `value` 累加，负值即负面）；`effects` 保留 `key/custom_key/text_key/value/storage_method/effect_sign/custom_args` 原始字段，供特殊效果规则表使用。英雄 `unlock_challenge` 由 `ChallengeService` 按名称关联（默认解锁英雄也可能带挑战数据）。
- **Tier 标注**：人工维护（社区共识 + 实机回放复盘修订），与自动数据分离；`ratings` 以物品 id 或武器族 `weapon_id` 为键（精确 id 优先）。
- **决策引擎加载**：`agent/ab_agent/knowledge.py` 的 `load_knowledge()` 读取并以 id 索引，启动时（`cli.py --knowledge-dir`，默认 `docs/knowledge`）校验四文件版本字段整备与 `game_version` 匹配，不匹配则告警。
- **更新流程**：部署新 mod → 启动游戏 → `python tools/export_knowledge.py` → `python tools/verify_knowledge.py` → 提交 JSON 变更。

## 8. 参数与调优（ADR-0008）

- 所有权重/阈值集中在 `agent/ab_agent/decision/config/`（JSON/YAML），代码不写死；
- **离线回放调参**：`tools/replay` 以录制回放驱动决策引擎，批量评估"若按参数集 P 行动，关键指标如何"（生存时长、受伤次数、材料收入）；
- 真实验收只用于最终确认（D0 10 局 ≥9 胜），不用于日常调参；
- 每次显著调参在回放库上留档对比结果。

### 8.1 回放分析指标（复盘模板）

- 死亡时刻状态：血量/位置/周围敌人密度/最近 3 秒受伤来源；
- 资源曲线：金币/材料收入 vs 波次；商店购买序列与评分明细；
- 走位指标：危险场均值、贴边时长、无谓受伤次数；
- 决策一致性：相同回放 + 固定随机种子 → 相同动作序列（反射层含平滑状态时以时间步重放）。

## 9. 已明确不做的事

- 不注入瞄准/开火（auto-aim 已由游戏提供）；
- 不直接修改游戏状态（数值/背包/金币/坐标）；
- 不使用暂停/时间加速等非正常手段提高胜率；
- 首版不做多英雄专门调优、不做 D1+ 专项策略、不做学习型策略（ADR-0002）。
