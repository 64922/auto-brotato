# ADR-0004：终端 CLI 交互；难度不钉死，接受任意已解锁等级

- 状态：已接受（2026-10-06）
- 关联：[architecture.md](../architecture.md) §4.2

## 背景

"系统提示用户选择难度"需要一个载体：终端 CLI、游戏内叠加层、外部 GUI 三选一。难度值也不能硬编码 D0：解锁按英雄/存档独立记录（`difficulty.max_selectable`），用户应能选择任意已解锁等级。备选：预置命令行参数（失去交互提示的本意，弃）。

## 决策

- 交互形态：终端 CLI。检测到难度页后打印英雄/初始武器/可选难度范围/模式开关，等待输入；支持 `status`、`stop`、`resume` 等命令与状态日志。
- 难度输入：接受 `D0`–`Dn`（n 为运行时读取的解锁上限）；非法/超范围/空输入重新询问重打印；D0 仅为示例。
- 开始前展示模式开关（endless/ban/zone 等）并二次确认，防止非预期模式开局。

## 理由

- 决策端本身即是常驻 Python 进程，终端是零成本入口，便于调试与观察；
- 叠加层交互需要处理输入捕获，易与游戏输入冲突；GUI 工作量中等，可后续作为薄壳（不改核心）；
- 运行时读取解锁范围保证与游戏状态一致，不引入硬编码维护点。

## 后果

- 运行期间需要一个终端窗口；游戏可后台运行（`pause_on_focus_lost=false`）；
- 未来加 GUI 时，CLI 交互逻辑应封装为独立模块以复用。
