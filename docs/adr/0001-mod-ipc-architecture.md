# ADR-0001：延续「mod 观测/动作注入 + Python 决策端」架构

- 状态：已接受（2026-10-06）
- 关联：[architecture.md](../architecture.md) §3、[protocol.md](../protocol.md)

## 背景

需要让系统自动完成 Brotato 整局对局。本机已有一套实机验证过的 AutoBrotato mod 0.2.0（战斗观测、move 注入、商店动作、IPC 均已跑通），但源码仅存于 workshop zip，Python 决策端与文档已丢失。备选方案为纯视觉外部 bot（截屏 + CV/OCR + 模拟输入）。

## 决策

延续既有架构：游戏内 mod 负责观测与动作注入，Python agent 经本机 TCP NDJSON 负责全部决策；以既有 0.2.0 zip 为源码基线重建仓库并补齐缺口（菜单/升级/决策端/文档）。保持不变量：mod 不直接修改游戏状态，动作只经游戏正常 `Input` 与 UI 信号。

## 理由

- 移动注入与商店链路已有实机验证，复用省去大量逆向与调参；
- 60Hz 结构化观测远优于像素级识别：弹幕/敌人速度、背包、属性、金币都是精确值；
- 纯视觉方案在实时避弹、菜单/卡片识别、失败恢复上均更脆弱；
- mod 方案与游戏更新绑定，但已决定锁版本 + 冒烟测试控制该风险（ADR-0005）。

## 后果

- 必须维护 mod↔agent 的协议契约（protocol.md）与游戏内部字段依赖清单（易碎点，§8）；
- 需要建立 mod 源码仓库与部署工具链（票据 01）；
- 原项目文档/票据编号（ADR-0006/0007、§4.x）已丢失，本文档集重建对应决策并保持编号稳定。
